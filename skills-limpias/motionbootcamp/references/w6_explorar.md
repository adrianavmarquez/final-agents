
# W6. Explore New USPs
## Fase Explore del Sprint Creativo · Jade Heritage (Calm) + Daniel Rivera (Harry's)

---

## CONTEXTO DE ACTIVACIÓN

Esta skill resuelve el momento en que el messaging core deja de funcionar o se agota. La señal de activación es: lo que antes era un workhorse ya no sostiene el crecimiento. El objetivo NO es producir mucho, es validar una hipótesis nueva con el mínimo de recursos.

**Principio rector:** "Always, always be open to new information. Things are always shifting."

**Diferencia crítica con W7:** Explore = encontrar. Exploit = escalar. Esta skill solo explora.

```
├── [OBLIGATORIO] Descripción del problema: ¿qué señal indica que hay que explorar?
│   ├── Ejemplo: "el CPA subió 40% en las últimas 4 semanas"
│   ├── Ejemplo: "el search term [X] está cayendo en Google Trends"
│   └── Ejemplo: "todos mis competidores están usando el mismo ángulo ahora"
├── [OBLIGATORIO] Producto o servicio a explorar
│   └── Si es PRODUCTO NUEVO en un catálogo existente: activar Protocolo Harry's

│   reviews de clientes, encuestas
└── [OPCIONAL] Budget para el test mínimo viable (afecta cuántos ads se proponen)

SEÑALES DE ACTIVACIÓN DE EXPLORACIÓN (identificar cuál aplica):
□ Declive en search trends del messaging core
□ Competidores copiando el mismo formato/ángulo (saturación)
□ CPA subiendo sin cambios en el producto
□ Nueva audiencia potencial no explotada
□ Nuevo producto o feature sin playbook creativo
□ Cambio en el lenguaje del consumidor (nuevo vocabulario emergente)
```

## PROTOCOLO DE RAZONAMIENTO INTERNO

```
PASO 1. Identificar el tipo de exploración necesaria
  ↳ ¿Es el LENGUAJE lo que cambió? (nueva terminología en el mercado)
     → Investigar organic social, comentarios, Google Trends
  ↳ ¿Es la AUDIENCIA lo que cambió? (el comprador real no es quien pensábamos)
     → Investigar reviews, surveys, datos de compra reales
  ↳ ¿Es el PRODUCTO lo que cambió? (nuevo SKU, nueva feature)
     → Protocolo Harry's: no asumir que el playbook anterior aplica
  ↳ ¿Es el MERCADO lo que cambió? (saturación, competidores copiando)
     → Investigar diferenciación: ¿qué NO está haciendo nadie?

PASO 2. Rastrear señales en fuentes externas
  ↳ Google Trends: ¿qué términos están subiendo? ¿cuáles cayeron?
  ↳ TikTok orgánico: ¿qué formatos y lenguaje están resonando en comentarios?
  ↳ Reviews propias y de competidores: ¿qué lenguaje usan los clientes?
  ↳ Reddit/foros de la industria: ¿qué problemas no resueltos emergen?

PASO 3. Conectar señal con assets existentes del producto
  ↳ ¿Ya existe algo en el producto que se alinee con la señal?
  ↳ ¿Se puede hacer messaging sobre una feature existente que no se ha publicitado?
  ↳ ¿Se necesita un nuevo feature para hacer ads de esto? (reverse engineering de Jade)

PASO 4. Evaluar viabilidad del claim
  ↳ ¿El claim es responsable? ¿Tiene respaldo científico o de datos?
  ↳ ¿Hay implicaciones clínicas, legales o éticas que acoten el messaging?
  ↳ Hacer la distinción: "esto es lo que el producto hace" vs. "esto es lo que estamos afirmando en publicidad"

PASO 5. Formular la hipótesis de exploración
  ↳ Formato: "[señal detectada] + [asset del producto] = [hipótesis de messaging]"
  ↳ Ejemplo Calm: "people searching nervous system regulation + bilateral audio in app
     = hypothesis: bilateral audio reduces anxiety better than meditation framing"
  ↳ Definir: ¿qué métricas validarían esta hipótesis como TRUE?

PASO 6. Diseñar el test mínimo viable
  ↳ 3 ads máximo para validación inicial
  ↳ Spend controlado, el objetivo es señal, no escala
  ↳ Proponer formatos: 2 in-house (scripts diferentes) + 1 UGC simple
  ↳ Foco del test: messaging, no producción. Control visuales para aislar la variable
```

## INSTRUCCIONES OPERATIVAS (SOP)

**Detección de señales:**
- Si el usuario tiene acceso a Google Trends: solicitar captura del término clave + términos emergentes
- Si el usuario tiene acceso a TikTok orgánico: buscar contenido viral relacionado, leer comentarios para validar respuesta emocional
- Siempre preguntar: "¿qué terminología nueva están usando tus clientes que antes no usaban?"

**Protocolo Harry's (producto nuevo o nueva línea):**
- NO aplicar el playbook del producto anterior sin validar
- Confirmar: ¿es el mismo comprador? Puede ser diferente (ej: women buying for their husbands)
- Testear el lenguaje primero: ¿el target entiende los términos técnicos que se quieren usar?
- Si hay lenguaje técnico (parabens, sulfates, bilateral stimulation): traducir a beneficio antes de usar en ads
- Si hay referencia de credibilidad (Kiehl's, Harvard, etc.): verificar que resuene en el segmento geográfico real

**Formulación de hipótesis:**
- La hipótesis debe ser falsifiable: debe poder resultar TRUE o FALSE
- Incluir siempre: ¿qué ángulo? ¿para qué persona? ¿con qué claim?
- Separar: product truth (lo que el producto hace) vs. customer truth (lo que el cliente siente/cree)
- La customer truth siempre tiene prioridad en el messaging

**Diseño del test:**
- Mínimo 3 ads, máximo 5 para una primera validación
- Usar proven ad formulas como control visual → solo cambiar el messaging
- Incluir siempre un enfoque educativo si el término/concepto es nuevo para el mercado
- Definir antes de lanzar: ¿qué métricas en qué umbral significan "hay señal"?

**Escalado preventivo:**
- Esta skill NO escala. Si hay señal positiva → handoff a W7_Exploit
- Si alguien pide escalar antes de validar: explicar que escalar sin validación es el error más caro
- El umbral de Jade: "si en un mes los costos casi se reducen a la mitad, hay señal para escalar"

**Sobre la persistencia:**
- Si un ángulo fue testeado antes y "no funcionó": preguntar cuándo y con qué ejecución
- Muchas veces el ángulo no falló, falló la ejecución o el timing de mercado
- "We already tried that and it didn't work" es el sesgo más común que bloquea el crecimiento

## GUARDRAILS

```
PROHIBIDO:
✗ Escalar la hipótesis antes de validarla con 3 ads mínimos
✗ Asumir que el playbook de un producto aplica a otro sin investigar
✗ Usar referencias de credibilidad sin validar que resuenen en el target geográfico
✗ Usar lenguaje técnico en ads sin verificar que el target lo entiende
✗ Hacer claims clínicos o terapéuticos sin respaldo científico revisado
  → Distinción obligatoria: "esto usa técnicas similares a X" ≠ "esto es X"
✗ Sobre-optimizar el primer test → usar proven formulas como control visual
✗ Descartar una hipótesis después de un solo test fallido sin analizar la ejecución
✗ Ignorar señales de organic social por "no ser datos de paid"

ADVERTENCIA ACTIVA:
⚠ Protocolo Harry's: si es producto nuevo, TODA la investigación de cliente
  se hace desde cero. El buyer puede ser completamente diferente.
⚠ Si el claim tiene implicaciones de salud, clínicas o reguladas:
  investigar el contexto científico ANTES de escribir el ad
⚠ "El ángulo de anxiety ya no funciona" ≠ "anxiety es un ángulo muerto" →
  puede ser que el ángulo funcione con diferente vocabulario (nervous system)
```

## ESCENARIOS DE ERROR Y RESOLUCIÓN

```
ERROR 1: No hay señales claras de qué explorar
→ Iniciar con análisis de Google Trends del término core del producto
→ Comparar con términos emergentes en la misma categoría
→ Revisar comentarios de los últimos 3 meses en organic social del brand y competidores
→ Si aún no hay señal: proponer test de 3 ángulos distintos de conciencia del problema

ERROR 2: El usuario quiere escalar inmediatamente sin validar
→ No bloquear, pero documentar el riesgo explícitamente:
   "Escalar sin validación mínima aumenta el riesgo de gastar en un ángulo
   que el mercado no responde. Recomiendo 3 ads de validación antes de escalar."
→ Si insiste: ejecutar con 3 ads de test embebidos en la escala para capturar señal

ERROR 3: El claim tiene implicaciones clínicas o reguladas
→ Solicitar respaldo: ¿hay estudios? ¿hay disclaimers legales disponibles?
→ Proponer el messaging más conservador que siga siendo verdadero
→ Distinguir explícitamente en el brief: "podemos decir [X]", "no podemos decir [Y]"

ERROR 4: El producto nuevo tiene el mismo comprador que el anterior (no necesita Protocolo Harry's)
→ Verificar activamente con data: ¿los compradores de los dos productos se solapan?
→ Si hay solapamiento >70%: proceder con versión adaptada del playbook anterior
→ Si hay solapamiento <70%: Protocolo Harry's completo

ERROR 5: El ángulo fue testeado antes con malos resultados
→ Investigar: ¿cuándo? ¿con qué ejecución? ¿con qué presupuesto?
→ Si el mercado cambió desde el test anterior: proponer re-test con nueva ejecución
→ Si la ejecución anterior fue débil: reformular la hipótesis con mejor producción

ERROR 6: Hay demasiadas hipótesis y el usuario no sabe cuál priorizar
→ Usar Evidence Ranking de W3: ¿cuál tiene más señales de mercado (Trend + organic + reviews)?
→ Priorizar la hipótesis con mayor intensidad de señal, no la más creativa
→ Las demás van al icebox para el próximo ciclo de exploración
```
